### #8 [gated_auto → downstream-resolver] M-2 / adv-001 — tasks block escapes strictness on both sides of contract

- **Files:** `packages/shared/src/schemas/index.ts` (`campaignTaskStatsSchema`), `packages/openapi/dashboard-api.yaml` (`DashboardStats.properties.tasks`)
- **Reviewers:** maintainability, adversarial
- **Confidence:** 75
- **Why:** `campaignTaskStatsSchema` is non-strict and the OpenAPI tasks block omits `additionalProperties: false`. A future change adding e.g. a `cancelled` top-level field to tasks would slip past Zod, OpenAPI, and the contract test simultaneously. ### #10 [manual → downstream-resolver] adv-002 — task-status bucket mapping as bare string literals risks silent zeroing on rename

- **File:** `packages/backend/src/routes/dashboard/stats.ts`
- **Reviewer:** adversarial
- **Confidence:** 75
- **Why:** A future DB migration renaming `exhausted` to e.g. `completed_with_partial_keyspace` would zero `tasks.completed` while `total` stays correct. Existing tests hardcode the same literals so the regression would be invisible in CI. Same shape for `assigned → running` and `cancelled → failed`.
- **Suggested fix:** Centralize the bucket mapping in `@hashhive/shared` (e.g., `TASK_DB_STATUS_TO_BUCKET: Record<TaskDbStatus, TaskBucket>`) and reference it from both `stats.ts` and `getCampaignTaskStats` so the two consumers can never drift.
